## 1. 제품 방향

첫 번째 분석의 **근거 중심 매각제안서, 매물 유형별 쇼룸**을 제품 중심으로 삼고, 두 번째 분석의 **최소 정보 등록, 선택적 자료 첨부, 자료별 생성 범위, 공개 전 검수**를 제작 흐름에 반영한다.

고객은 실제 매물의 조건과 검토 이유를 먼저 확인하고, 이어 AI 활용안을 탐색한다. AI 활용안은 허가·설비·수익이 확인된 사실로 표현하지 않는다. 장안리 공장과 점봉동 쿠팡 물류센터는 별개 매물이다. 후자의 수치·사진·도면·임대조건을 전자에 전용하지 않는다.

기본 디자인·자료 관리·문의·검수는 공유하되, 화면의 주요 정보와 순서는 매물 유형에 맞게 구성한다. 유형별 콘텐츠가 단순 제목 교체에 머물러서는 안 된다.

## 2. 고객 화면 구성

| 유형 | 주요 정보 및 화면 흐름 |
| --- | --- |
| 공장·산업용 (우선 구현) | 요약·검토 이유 → 토지/건물 → 설비·전력·층고/하중 → 입지·진입/차량·작업 동선 → 제공 도면 → AI 활용안 → 근거/확인사항 → 문의 |
| 상가 | 요약 → 층수·면적·거래조건 → 출입·주차·시설 → 확인된 상권 자료 → 업종 활용안 → 자료/문의 |
| 토지 | 요약 → 지번·지목·면적 → 용도지역·이용규제 → 접도·진입·기반시설 → 개발 활용 가설 → 자료/문의 |
| 물류센터 | 요약 → 층별 구조·상온/저온 → 도크·차량 동선 → 교통망 → 임차/운영 자료 → 활용안 → 자료/문의 |

임대·운영·수익 분석은 유형에 덧붙일 수 있는 모듈로 설계한다. 상가·공장·물류에도 적용될 수 있다. 기존 `income` 유형은 유지하고, 수익형 건물 독립 화면 지원 범위는 후속 단계에서 확정한다. 기존 `industrial`을 근거 없이 공장 또는 물류 중 하나로 단정하지 않는다.

### 표시 및 생략 규칙

- 핵심 검토 이유는 최대 3개. 출처·검증 상태·제약을 함께 보여준다. 자료가 부족하면 억지로 개수를 채우지 않는다.
- 자료가 없는 중요 조건은 확인 필요로 표시한다. 무관한 분석 모듈은 생략한다.
- 도면이 없으면 실제 도면을 재현한 화면으로 표현하지 않는다. 개념적 구역 안내는 별도 표시한다.
- 실사진이 없으면 현장 실사진 미제공 상태를 표시하고 AI 이미지와 구분한다.
- 임대·운영 자료가 없으면 실제 수익 지표를 만들지 않는다. 가정 계산은 실제 임대수익과 분리한다.
- 위치 안내와 검증된 입지 분석을 구분한다. 외부 지도·시장 데이터를 아직 연동하지 않았다는 점을 숨기지 않는다.

## 3. 제작 흐름과 입력

유형/거래방식 선택 → 최소 정보 임시 저장 → 자료 선택 첨부 → 자료 정리/AI 초안 생성 → 사실·문구·이미지·권한 검수 → 승인본 공개 → 문의 관리.

공통 입력: 유형, 거래방식, 매물명, 주소/지번, 확인 가능한 면적과 단위, 가격/임대조건 또는 협의 상태, 담당자. 누락이 있어도 임시 저장 가능. 공개 필수 조건은 서버에서 확인한다. 유형별 상세 항목은 필요할 때 펼친다.

자료 수준 A~D는 엄격한 등급이 아니라 보유 자료에 따른 기능 조합이다. 기본정보만 있으면 개념 이미지, 도면이 있으면 도면 기반 안내, 실사진이 있으면 현황/예상 비교, 제안서·운영 자료가 있으면 상세 자산/임대 모듈을 지원한다. 제안서만 있고 실사진이 없는 조합도 허용한다. **자료의 양은 사실 검증 수준을 뜻하지 않는다.**

## 4. 데이터와 권한 원칙

- 값·단위·출처·원문 위치·확인 기준일/확인자 등 검증 기록을 관리한다. 누락값과 숫자 0, 가격 협의 상태를 구분한다.
- 상태: 확인됨 / 제공정보 / 자료 기반 추론 / AI 생성 / 확인 필요. 현재 4종 상태와의 호환·변환을 먼저 설계한다. 기존 `verified`를 증빙 확인 완료로 일괄 승격하지 않는다.
- 검증 상태와 공개 권한을 별도로 관리한다. 원본, 추출값, 이미지 각각의 사용·공개 범위를 다룬다.
- AI 이미지: 개념형 / 도면 기반 / 현장 사진 기반. 유형·근거자료·표시 문구를 유지한다. 구조 보존 자동 검수는 보조 기능이며 사람의 최종 확인을 대체하지 않는다.
- 비공개 초안과 승인본을 분리한다. 초안 수정은 재승인 전 공개본에 반영하지 않는다.
- 기존 데이터와 승인본을 유지하는 추가적 변경부터 적용한다. API 공개 응답과 두 Python/TS 초안 생성 경로의 호환을 검증한다.

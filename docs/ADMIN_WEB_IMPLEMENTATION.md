## W1 / W2 첫 단위 — 원문과 접수·저장 복구

2026-11-07 한국시간. 새 동작은 서버 `ADMIN_WEB_ENABLED=true`로 구분하며 기본 비활성화다. 전체 전환의 서버/작업자 준비 전 운영에서 켰다고 표시하지 않는다. 설정이 꺼져 있으면 기존 등록 UI/API가 유지된다.

구현:

- 새 등록을 시작하면 원자적으로 비공개 매물·웹 접수·초안·미실행 작업을 만들고 실제 접수 번호/시각을 표시한다. 초기 생성 응답이 유실되면 같은 request ID로 조회하거나 재요청한다.
- 간단/자료 입력과 현재 원문을 서버에 자동 저장한다. 원문·연락처를 브라우저 저장소에 넣지 않고 미완료 접수 식별자만 sessionStorage에 보관한다.
- 1.2초 지연 저장, 즉시 저장, 저장본 복구, 확정 후 검토실 이동을 제공한다. 저장 실패/결과 불명은 입력을 유지하고 같은 쓰기 요청을 재확인한다. 이후 입력을 다시 저장할 때도 과거 저장 응답을 새 입력에 덮어쓰지 않는다.
- 웹 입력 원문은 private input_payload/원문 버전으로 보존한다. 고객 요약과 구분하고 기존 매물의 요약을 원문으로 자동 승격하지 않는다. 원문만 고치면 기존 고객 문안·공개본을 보존하고 revision을 갱신한다.
- source/query/write의 사용자 ID는 인증 API에서 결정한다. 같은 요청의 다른 내용, 다른 사용자 접수, 오래된 revision, 이미 닫힌 등록 양식을 거절한다.
- 접수/저장 멱등성은 source와 표준화한 등록 입력 기준으로 검사한다. 저장 응답 재전송은 현재 초안과 다시 합치기 전에 기존 쓰기 기록을 조회하여 중복 반영과 과거 수정 덮어쓰기를 막는다.
- 사진·도면·PDF는 기존 비공개 업로드를 재사용하고 저장된 파일 목록을 보여준다. 등록·업로드 자체로 AI 생성 요청을 시작하지 않는다. 수동 이미지 정책을 명시하고 이전 자동 이미지 스캔의 opt-in 값은 부여하지 않는다.
- 검토실의 원문 영역에서 접수/버전을 보고 별도로 저장한다. 저장하지 않은 원문이 있으면 분석을 시작하지 않는다. 향상된 웹 분석 입력은 저장된 원문과 사용 가능한 제공/검증 필드를 사용하고, 편집한 AI 요약은 원자료로 보내지 않는다.

추가 migration: `20261107040000_web_intake_recovery.sql`. 기존 web 접수에 원문/버전/등록 완료 상태를 추가하고 private 원문 버전·쓰기 식별 이력 및 service-only RPC를 더한다. 기존 행은 원문 미확인·등록 양식 종료 상태로 둔다. 기존 승인본/원문을 일괄 변환하지 않는다.

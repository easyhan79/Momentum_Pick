# 관리자 웹 전환·검증·복구

기준: 2026-11-07 한국시간. 이 문서와 서비스 파일은 **배포 준비물**이다. 실제 호스트 설치·Supabase migration·함수 배포·사이트 게시·키 활성화를 실행한 기록은 아니다.

## 사용할 때

1. 매물 검토실 → 새 매물 입력. 간단 입력/자료로 등록 중 선택한다. 원문은 고객 요약과 별도로 저장한다.
2. 저장 번호와 시각을 확인한다. 응답이 끊기면 같은 접수/저장 요청을 다시 확인한다. 원문은 브라우저 저장소에 복제하지 않는다.
3. 첨부는 개별 파일로 비공개 보관한다. 사용할 PDF를 사실정보 편집에서 선택한다. 사진 업로드는 사진의 AI 분석 완료를 뜻하지 않는다.
4. 등록 완료 후 저장된 자료로 분석 시작. 작업자 연결이 끊겨도 접수는 DB에 남고, 연결 상태와 단계가 화면에 표시된다.
5. 완료 결과를 비교하고 헤드라인/요약/광고 문안/활용 콘셉트/자료 추출 후보를 선택한다. 값 후보는 원문 대조 후 사실정보에 별도 반영한다. 작성 후 초안·원문이 바뀌면 이전 결과의 적용을 차단한다.
6. 문안이 마음에 들지 않으면 다시 글작성에서 항목·작성 방향을 고른다. 새 결과를 비교하고 적용한다.
7. 이미지 프롬프트 복사 → Gemini 웹에서 생성/편집 → AI 이미지 비공개 보관. 제작 도구·사용 프롬프트·참고 자료·사용 권한과 AI 예상도 분류를 유지한다. 기존/새 이미지를 비교해 대표 또는 콘셉트에 배치한다.
8. 저장·미리보기·자료/구조 대조·검수·게시. 분석 완료·이미지 업로드는 게시 승인이 아니다.

## 실행자 설치 전 확인

- 실제 제공자·실행 대상·유지 비용·호스트 접근권한·본인 Auth ID·격리 프로젝트를 먼저 확인한다. 미확인 대상을 임의 생성하거나 유료 계약하지 않는다.
- Python 3.12 이상, 전용 가상환경, `requirements-web-worker.txt`를 사용한다. 신규 프로세스는 `web_worker.py`이며 `analysis_worker.main()`을 호출하지 않는다.
- `deploy/web-worker/spacepick-web-worker.service`는 systemd 예시다. 실제 호스트에 맞춘 경로/리소스 검토 후 설치한다. 환경 파일은 서버의 `/etc/spacepick/web-worker.env`에 600 권한으로 보관한다. 소스 저장소·웹 bundle·채팅에 비밀값을 넣지 않는다.
- `WORKER_ENVIRONMENT=staging/test`는 운영 ref를 거절하고, production은 운영 ref와 일치해야 한다. URL/key 역할도 검사한다. 새 Supabase secret은 API gateway가 역할을 검증하며 코드가 토큰을 출력하지 않는다.
- `WEB_WORKER_ENABLED`와 Edge의 `ADMIN_WEB_ENABLED`, `WEB_PROCESSING_ENABLED`는 별개다. 모든 기본값은 OFF. API 이미지는 Edge와 worker 양쪽 `WEB_API_IMAGES_ENABLED`가 켜져야 하며 요청별 비용 확인도 필요하다.
- 실행 명령: `python web_worker.py --once`로 한 회차 확인 후 상시 서비스를 시작한다. `--once`도 실행 중인 프로젝트의 실제 유료 작업을 처리할 수 있으므로 격리 프로젝트에서 먼저 사용한다.
- 작업자 heartbeat는 20초마다 독립 갱신한다. 분석 lease도 별도 갱신한다. 오래된 heartbeat를 정상 연결로 표시하지 않는다. SIGTERM은 진행 작업의 결과 저장 후 종료하며 종료 유예는 360초다.

## migration/함수/사이트 순서

1. 읽기 전용 inventory·현재 migration 목록·배포 commit·승인 snapshot digest·queue 예산/회수·롤백 기준을 기록한다. 민감한 원문·연락처를 운영 로그에 복사하지 않는다.
2. 기존 migration 전체 적용 여부를 대조한 뒤 새 `20261107040000`~`20261107070000`을 순서대로 적용한다. 기존 열/작업/승인본을 삭제하거나 기존 원문을 AI 문안으로 채우지 않는다. 060000은 기존 copy/image 함수와 050000, 070000은 기존 concept 함수와 060000에 의존한다.
3. 새 Edge 함수와 새 필터가 있는 legacy Python을 배포하되 flags OFF. **migration만 먼저 적용하고 오래된 이미지/도면 worker를 계속 실행하면 안전한 전환으로 볼 수 없다.** 새 legacy worker는 명시적인 web 작업을 건너뛴다.
4. 격리 프로젝트에서 본인 접근 제한과 환경별 URL/키/리다이렉트 검사를 통과한다. 본인 전용 frontend·owner guard·worker를 같은 릴리스로 연결한다.
5. synthetic 5유형과 PDF/자료 없는 경우, 실패/응답 유실/재로그인/취소/동시 실행을 검증한다. 실제 AI 1건은 공급자·비용·출력 품질·권리 조건을 기록한다. 모의 AI 통과를 실제 품질/비용 검증으로 쓰지 않는다.
6. 선택한 매물만 pilot으로 등록/재개한다. 기존 pending/진행 중인 legacy 작업은 자동 이동하지 않는다. 유효 legacy claim은 완료/만료·결과 확인 전 새 실행자에 넘기지 않는다. 새 요청은 transaction 안에서 실행자와 snapshot을 함께 고정한다.
7. 실제 관측 결과와 배포 commit/프로젝트/본인 계정/시각을 RUN_STATE·PROGRESS에 기록한 뒤 운영 전환한다. Telegram 신규 접수를 끄는 결정은 웹 접수·실제 AI·승인·복구 검증 후 기록한다. 이 코드에는 운영 webhook 삭제/접수 기록 제거가 없다.

## 오류·재시도·복구

- 429 등 확인된 일시 오류는 기존 회수 상한에서 5/15/30/60분 후 재시도한다. 새 분석 요청은 매물별 1시간 3회, 회차당 분석 5회·재작성 3회, 이미지 누적 예약 예산을 보존한다. 재배포/lease 만료로 회수를 0으로 만들지 않는다.
- 공급자 timeout/응답 불명 또는 generating 중 프로세스 유실은 `outcome_unknown`: 자동 재호출을 멈춘다. 공급자 사용 이력 확인 후 새 요청을 명시적으로 시작한다. 외부 유료 호출의 exactly-once는 보장하지 않는다.
- AI 결과 candidate를 DB에 저장한 후 완료 응답만 끊기면 같은 candidate로 저장을 재개하며 AI를 재호출하지 않는다. candidate 저장 전 유실은 결과 불명으로 남을 수 있다.
- 취소는 claim token을 무효화한다. 이미 진행 중인 공급자 과금은 취소되지 않을 수 있다. 취소/구버전/새 원문 이후의 결과는 새 초안을 덮어쓰지 않는다.
- 수동 이미지 slot은 자동 sync/재생성에서 보호한다. 명시적으로 선택을 해제해야 API 제작이 가능하다. 콘셉트가 바뀌면 해당 수동 연결도 해제하고 원본 AI 파일은 비공개로 보관한다.
- 부분 장애 시 저장/원문/파일 보관/이미지 프롬프트는 유지한다. 분석/문안/도면/선택 API 이미지의 실패가 서로의 저장 결과를 취소하지 않는다.

## 롤백

1. 신규 웹 처리 접수를 flag로 중단하고 worker에 SIGTERM을 보내 정상 종료를 기다린다. 유효 lease가 남았으면 기존 프로세스와 새 프로세스를 함께 시작하지 않는다.
2. 실패 지점·현재 executor·candidate·lease·회수·예산을 읽기 확인한다. pending web 행을 자동 legacy로 전환하거나 attempt/budget를 초기화하지 않는다.
3. 프런트/Edge를 이전 안전 버전으로 되돌려도 **실행자 필터가 있는 DB 함수/worker는 유지**한다. 필터 없는 오래된 `analysis_claim`을 복원하면 web 큐를 훔칠 수 있다. additive migration은 삭제하지 않는다.
4. 공개 쇼룸은 기존 published snapshot을 계속 사용한다. 새 분석/선택 이미지가 공개 snapshot을 변경하지 않았는지 digest를 대조한다. 되돌리기를 이유로 기존 승인본을 재게시하지 않는다.
5. 수정 버전으로 web 실행자를 재개해 candidate 저장/미실행 작업부터 처리한다. 실제 복구 시각·버전·처리 전후 수치가 없으면 복구 완료로 기록하지 않는다.

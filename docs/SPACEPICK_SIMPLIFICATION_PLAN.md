## 1. 목표

관리자는 두 번만 확인하고, 나머지는 자동으로 진행한다.

1. 매물 정보를 입력하면 상권·입지를 먼저 분석한다.
2. 분석 결과로 기획서(누구에게, 무엇을, 어떤 톤으로 말할지)를 만든다.
3. 기획서에 맞춰 쇼룸 글 → 이미지 → 블로그 → 카드뉴스를 자동으로 만든다.
4. 미리보기를 확인하고 「게시」 한 번으로 웹쇼룸에 반영한다.

성공 기준

- 새 매물 하나를 입력부터 게시까지 진행할 때 사람이 확인하는 것은 2번이다.
- 필수 사실 4가지(주소, 거래방식·가격, 면적, 담당자 연락처)가 맞으면 게시가 거절되지 않는다.
- 게시가 안 될 때는 무엇을 어디서 고치면 되는지 한 문장으로 알려 준다.

## 2. 목표 흐름

```
① 입력: 주소, 거래방식·가격, 면적, 특징 메모, 사진·도면(여러 장 한 번에)
② [자동] 공공데이터 수집 + 상권·입지 분석
③ [자동] 기획서 작성
④ ✋ 확인 1: 필수 사실 4가지 + 핵심 장점 3개 + 글 톤
⑤ [자동] 쇼룸 글 → 글에 맞는 이미지 → 블로그 → 카드뉴스
⑥ ✋ 확인 2: 전체 미리보기 → 「게시」
```

### 확인 1에서 보는 것

| 항목 | 내용 |
| --- | --- |
| 필수 사실 | 주소, 거래방식·가격, 면적, 담당자 연락처 |
| 핵심 장점 3개 | 장점마다 근거(입력 자료 또는 공공데이터)를 함께 보여 준다. 빼거나 순서를 바꿀 수 있다. |
| 타깃 고객·글 톤 | 선택지에서 고른다. |

고칠 것이 없으면 「이대로 진행」 한 번으로 넘어간다.

### 확인 2에서 보는 것

- 쇼룸, 블로그, 카드뉴스를 탭으로 나눠 미리보기한다.
- 마음에 들지 않는 부분만 「다시 쓰기」하거나 직접 고친다.
- 「게시」를 한 번 누른다. 체크박스나 메모 입력은 없다. 누가 언제 게시했는지는 자동으로 기록한다.

### 자동 처리 원칙

- AI가 만든 이미지에는 "AI 예상 이미지" 라벨을 자동으로 붙인다. 이미지마다 승인 체크를 받지 않는다.
- 공공데이터에서 가져온 수치에는 출처와 기준일을 자동으로 표시한다.
- AI가 만든 숫자(유동인구, 예상 매출, 수익 등)는 고객 화면에 사실처럼 쓰지 않는다. 숫자는 입력 자료나 공공데이터에서 온 것만 쓴다.
- 지금 있는 자세한 편집 패널 17개는 「고급 편집」으로 접어 두고 필요할 때만 연다.

## 3. 현재 문제 (2026-11-12 코드 확인)

### 3-1. 게시가 막히는 이유

게시 버튼을 누르면 서버(`supabase/functions/showroom-admin/index.ts`의 publish 처리)가 아래를 모두 검사하고, 하나라도 걸리면 거절한다. 오류 문구는 `showroom-web/src/lib/adminApi.ts`에 있다.

| 오류 코드 | 거절 조건 | 문제점 |
| --- | --- | --- |
| `review_required` | 「저장본 검수 준비」를 먼저 누르지 않음 | 게시 전에 단계를 하나 더 거쳐야 한다. (안내 문구는 "먼저 「저장본 검수 준비」를 눌러 주세요."로 정확하다. 처음 분석 때 문구가 틀렸다고 적었으나 잘못 확인한 것이었다.) |
| `checklist_required` | 확인 체크 4개 + 메모 10자 이상 | 게시할 때마다 반복해야 한다. |
| `registration_contact_required` | 담당자 이름·전화번호·공개 동의 없음 | 필요한 조건이다. 유지한다. |
| `profile_review_required` | 아래 8가지 중 하나라도 해당 | 서로 다른 원인이 모두 같은 문장 하나로 표시된다. |
| `plan_analysis_pending` | 도면 분석이 대기·진행 중이거나 **실패** | 실패해도 게시가 계속 막힌다. |
| `content_review_required` | 매물명·헤드라인·요약 없음, 헤드라인 100자 초과 | 필요한 조건이다. 유지한다. |
| `plan_positions_required` | 도면 구역 번호 위치가 하나라도 비어 있음 | 번호만 숨기면 되는 문제로 게시를 막는다. |
| `image_generation_pending` | 이미지 생성이 대기·진행 중 | 자동 준비 기능이 이미지 작업을 자동으로 대기열에 넣는다(`web_worker.py`의 `prepare_automatic`). 처리가 늦으면 게시가 계속 막힌다. |
| `revision_conflict` | 화면을 연 뒤 초안 버전이 바뀜 | 백그라운드 자동 준비가 초안을 고치면 생기는 것으로 추정한다. 아래 "빠져나갈 수 없는 막힘" 참고. |

**빠져나갈 수 없는 막힘 (2026-11-12 확인, GitHub 코드와 운영 번들 모두 같음)**

사용자가 실제로 겪은 증상은 "변경됐습니다" 안내만 나오고 다음으로 진행되지 않는 것이다. 코드상 다음 순서로 막힌다.

1. 사실정보 체크나 문구 수정 → 화면이 "저장 전 수정 있음" 상태가 된다.
2. 그 사이 다른 작업(광고 자동 준비, 이미지 생성, 다른 탭 등)이 같은 초안을 고쳐 서버의 저장 버전 번호가 올라간다.
3. 「초안 저장」 → 버전이 달라 서버가 거절한다(409). 안내: "분석 결과 또는 초안 버전이 바뀌었습니다" 또는 "자료 상태나 저장 버전이 변경됐습니다". 저장이 실패했으므로 "저장 전 수정 있음"은 그대로 남는다.
4. 「최신 저장본 불러오기」, 「저장본 검수 준비」, 게시는 "저장 전 수정 있음"이면 잠긴다(`PublishPanel.tsx`의 `disabled={…||dirty}`, `AdminPropertyPage.tsx`의 `reloadDraft`).
5. 화면 안에서는 빠져나갈 버튼이 없다. 새로고침하거나 등록 매물 목록에서 「초안 열기」를 다시 눌러야 한다(저장 안 한 수정은 사라짐).

당장 피하는 방법: 새로고침 → 로그인 → 자동 준비·이미지 생성이 끝났는지 확인 → 수정·체크 후 바로 「초안 저장」 → 곧바로 「저장본 검수 준비」 → 확인 4개·메모 → 게시.

`profile_review_required`의 세부 원인(`supabase/functions/_shared/property-profile.ts`의 `profilePublicationIssues`):

1. 세부 유형을 고르지 않음
2. 거래방식을 고르지 않음
3. 소재지가 없음
4. 가격 상태를 확인하지 않음
5. 거래방식에 맞는 가격이 없음
6. 공개 가능한 면적이 없음. 면적 하나가 통과하려면 ㎡ 숫자, 출처 문구, 공개 승인, 사용 권한, 연결 자료의 "파생 정보 공개 허용"이 모두 필요하다(`visibleField`).
7. 공개 승인한 항목 중 6번의 조건을 못 갖춘 항목이 있음
8. 근거 자료가 삭제됨, 목적별 판단 카드를 검토하지 않음, 임대 계산 입력이 범위를 벗어남

### 3-2. 관리자 화면 사용성

- 한 페이지에 패널 17개가 세로로 나열되어 있고 목차가 없다.
- 저장 버튼이 영역마다 따로 있다(초안, 입력 원문, 광고 초안, 컨셉존, 영문 주소). 저장하지 않고 나갈 때 경고하는 기능은 등록 양식에만 있다.
- 면적은 ㎡, 가격은 원 단위로만 입력한다. 300억을 입력하려면 `30,000,000,000`을 쳐야 한다.
- 파일은 한 번에 하나씩만 올릴 수 있고 드래그 앤 드롭이 없다.
- 로그인이 현재 탭에만 유지되어 새로고침하면 다시 로그인해야 한다.
- AI 이미지 1장을 넣는 데 수작업이 10단계 이상 걸린다(프롬프트 복사 → Gemini 웹 → 다운로드 → 업로드 → 정보 입력 → 교체).

### 3-3. 고객 화면 품질

- 모든 매물 사진에 어둡게 하는 필터가 걸려 있다: `showroom-web/src/styles.css`의 `.asset-image img{filter:saturate(.65) brightness(.75)}`.
- 도면과 AI 이미지가 잘린다: 전역 규칙 `img{width:100%;height:100%;object-fit:cover}`.
- 헤드라인 둘째 줄이 사라진다: `Hero.tsx`가 subtitle의 첫 줄만 쓴다.
- 9px 이하 글자 규칙이 47개이고(최소 6px), 지정한 Pretendard 폰트를 실제로 불러오지 않는다.
- 히어로 바로 아래가 "확인 필요 · 자료 미제공" 카드로 가득하다.
- 내부 용어("제공 HTML 예시", "합성 fixtures")가 고객에게 보이고, 샘플 선택 목록에 QA용 항목이 있다(`main.tsx`의 `labels`).
- AI 이미지 해상도가 1K(약 1024×576, `image_worker.py`)라 히어로에서 흐릿하다. 업로드 이미지는 리사이즈나 썸네일 없이 원본(최대 8MB)을 그대로 보낸다.

- [ ] **기획서 데이터 정의.** 타깃 고객, 핵심 장점 3개(각각 근거 출처 포함), 글 톤, 핵심 키워드, 피해야 할 표현. `sales_analysis.py`의 `SalesStrategy`(`positioning`, `sellingPoints`)를 확장해서 쓴다.

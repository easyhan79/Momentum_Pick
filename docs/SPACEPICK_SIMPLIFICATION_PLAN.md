## 1. 방향

> **SpacePick = 매물 하나를 입력하면 "매물 한 장 페이지 + 채널별 홍보글 + 문의 알림"을 바로 만들어 주는 도구. 고객은 그 페이지에서 자기 사업을 직접 계산해 본다.**

판단 기준은 하나다. **이 페이지를 본 사람이 연락하고 싶어지는가?** 이 질문에 도움이 안 되는 기능은 만들지 않는다.

### 차별점 세 가지

단순하게 만들되, 일반 홍보 페이지와 다른 점은 이 세 가지다.

1. **정직한 사실 정리**: 확인된 사실과 숫자만 쓰고, 핵심(주소·금액)은 눈에 띄게 보여 준다.
2. **대상에 맞춘 쓰임새 제안**: "임대합니다"가 아니라 "카페 창업자에게 이 공간을 제안합니다".
3. **고객이 직접 조작하는 계산기**: 예측이 아니라, 고객이 넣은 가정을 계산해 보여 준다.

### 왜 이렇게 정했나

- 지난 계획은 "관리자가 실수 없이 게시하는 시스템"을 목표로 해서 복잡해졌다. 기획서 승인, 3단계 흐름, AI 대기열, 이미지 예산, 카드뉴스, 공공데이터 파이프라인이 그렇다.
- AI 작업자가 몇 시간에 한 번만 돌아서, 몇 분이면 될 수정이 몇 시간 걸린다.
- 실제 매매제안서 2건을 손으로 만들어 보니 필요한 것은 단순했다. 사실 표, 핵심 숫자 강조, 쓰임새 제안, 계산, 사진, 연락처.
- "홍보글 → 매물 페이지 → 문의" 구조가 사용자가 처음부터 원하던 모습이었다(2026-11-14 사용자 확인).

## 2. 제품 정의

### 입력 (10개 안팎)

| 항목 | 예 |
| --- | --- |
| 매물 기본 | 주소, 층, 전용면적, 서비스 면적(테라스 등) |
| 거래 조건 | 매매가 또는 보증금·월세·관리비, 「협의」 가능 |
| 현재 상태 | 공실 / 영업 중(업종, 계약 만료일), 시설 인수 가능 여부 |
| 확실한 설비 | 층고, 전력, 가스, 상하수도, 주차 — 아는 것만 |
| 특징 메모 | 소유자·중개사가 아는 사실 몇 줄 |
| 사진 | 실제 사진 여러 장 |
| **누구에게 팔고 싶은가** | 예: 카페·필라테스 창업자 / 임대수익 투자자 / 공장을 직접 쓸 기업 |
| 연락 방법 | 전화·문자·당근 채팅 등 |

### 출력

1. **매물 한 장 페이지** (`spacepick.kr/<주소이름>`): 실제 사진, 핵심 숫자, 쓰임새 제안, 계산기(필요할 때만), 위치, 문의 양식. 휴대폰 우선.
2. **채널별 홍보글**: 당근마켓, 네이버 블로그, 카카오톡 공유 문구. 모두 매물 페이지 링크로 이어진다.
3. **문의 알림**: 페이지에서 문의가 오면 텔레그램으로 바로 알린다(기존 기능).
4. **PDF** (C단계): 같은 내용을 A4 1장 요약 또는 여러 쪽 제안서로. 의뢰인 로고·연락처를 넣는다.

### 페이지 구성 (매물에 따라 순서 조정·생략 가능)

1. 대표 영역: 실제 대표 사진, 매물명, 거래 유형, 한 줄 제안
2. 매물 정보: 위치, 가격·조건, 면적·층·용도, 설비, 사진·도면
3. 쓰임새 제안: 대상 고객에게 맞춘 활용 아이디어 2~3개(필요하면 「AI 예상 이미지」 1장)
4. 계산기: 매물당 0~2개(4장)
5. 위치: 지도와 주변 시설(카카오 데이터, 출처·기준일 표시)
6. 문의: 문의하기, 현장 방문 요청, 추가 자료 요청
7. 하단: 자동 면책 문구(계산기·AI 이미지·추정치가 있을 때)

### 원칙 — 정직한 광고

- 숫자는 입력한 사실이나 공공데이터에서 온 것만 쓴다. AI가 매물 숫자를 만들지 않는다.
- 사진은 실제 사진만 쓴다. AI 구상 이미지는 「AI 예상 이미지」로 표시하고 선택 사항으로 둔다.
- 거래 조건은 공개하거나 「협의」라고 솔직하게 쓴다. 연락처를 남겨야 조건을 알려 주는 방식은 쓰지 않는다.
- "확정·보장·100%" 같은 표현은 쓰지 않는다.
- 주소와 금액 같은 핵심 정보는 눈에 띄게(붉은 굵은 글씨 등) 보여 준다.

### 만드는 흐름

```
입력(10칸 + 사진 + 누구에게) → [AI 수 초] 페이지 문구·홍보글 초안 → 화면에서 바로 고치기 → 「올리기」
```

승인 단계와 대기열은 없다. 계산기는 AI를 부르지 않고 브라우저에서 바로 계산한다.

## 3. 대상별 양식

| 양식 | 보는 사람 | 강조할 것 | 기본 계산기 | 단계 |
| --- | --- | --- | --- | --- |
| 창업자용 (상가 임대) | 카페·학원·필라테스 창업자 | 면적·서비스 면적, 설비, 업종별 쓰임새, 초기 비용(권리금·시설 인수) | 카페·음식점 매출 | A·B |
| 투자자용 (수익형 매매) | 임대수익을 사려는 사람 | 임차인, 보증금·월세, 계약 기간 | 수익률 | C |
| 실사용 매수자용 (공장·물류) | 직접 쓸 기업 | 개요 표, 층고·전력·용도지역, IC 거리, 확장안 | 평당가·확장 후 단가 | C |

## 4. 계산기(시뮬레이터) 설계

### 원칙

1. 계산기는 **미래를 예측하는 도구가 아니라 고객의 가정을 계산하는 도구**다. 매출·수익을 예측하거나 보장하지 않는다.
2. 세 가지를 화면에서 구분한다.

   | 구분 | 뜻 | 예 |
   | --- | --- | --- |
   | 매물 사실 | 자료로 확인한 값 | 전용 50평, 테라스 10평 |
   | 고객 가정 | 고객이 바꾸는 값 | 테이블 수, 객단가, 회전수 |
   | 계산 결과 | 가정을 공식에 넣은 값 | 가상 월매출 |

3. 초기값은 편의를 위한 **예시**라고 표시한다. 지역 평균이나 예상 실적처럼 쓰지 않는다. 「초기값으로」 버튼을 둔다.
4. 계산식을 화면에 보여 준다. 수익률은 포함·제외한 비용을 적는다.
5. 계산은 **미리 만든 계산기 부품**이 브라우저에서 한다. AI는 어떤 계산기를 쓸지 제안만 한다. AI가 만든 코드나 문자열을 실행하지 않는다.
6. 매물당 0~2개. 맞지 않는 매물은 계산기를 넣지 않는다. 계산기가 없어도 페이지는 정상으로 보인다.
7. 계산기 종류는 **실제 필요한 것부터 하나씩** 만든다. 처음은 카페·음식점 하나다.
8. 고객이 계산기에 넣은 값을 연락처와 묶어 자동 수집하지 않는다.

### 계산기 목록

| 계산기 | 입력(고객 가정) | 결과 | 만들 때 |
| --- | --- | --- | --- |
| 카페·음식점 매출 | 테이블 수, 테이블당 결제액, 하루 회전수, 월 영업일 | 가상 일·월·연 매출 | A단계(201호) |
| 수익형 건물 수익률 | 매입가, 보증금, 월세, 공실률, 운영비, 대출 금리(선택) | 연 임대수입, 단순 수익률, 비용 반영 수익률 | C단계 |
| 실사용 평당가·확장 | 매매가, 대지·연면적, 추가 부지 면적·단가 | 대지·연면적 평당가, 확장 후 평당가 | C단계 |
| 학원·교육 | 수강생 수, 월 수강료, 반 수 | 월 수강료 매출 | 실제 매물이 생기면 |
| 예약제 서비스 | 하루 예약 수, 건당 결제액, 월 운영일 | 가상 월매출 | 실제 매물이 생기면 |
| 공장·물류 운영비 | 월 운송 횟수, 건당 운송비, 보관 수량 | 가정한 운송비·보관량 | 실제 매물이 생기면 |

## 5. 고객과 사업 순서

1. **사장님 상가(테라스 상가 201호)**: 첫 매물이자 첫 검증. 페이지와 홍보글을 2~4주 올려 조회와 문의가 실제로 오는지 본다.
2. **다른 건물주(임대인)**: 효과가 확인되면 "공실 홍보 페이지 제작"을 부업으로 판다. 건당 제작비 또는 작은 월 요금. 프리랜서 플랫폼, 지역 광고로 고객을 모은다.
3. **B2B 제안서(PDF)**: 지인 물류 컨설턴트 같은 의뢰인에게 같은 도구로 PDF 제안서를 만든다. 조건(건당 금액)을 미리 정하고, 아니면 호의로 돕는 일로 본다.
4. **공인중개사용**: 검증 이후에 판단한다. 광고 법정 표시사항, 사무소별 계정 분리가 필요해 일이 많다.

수익은 **제작비·구독료**로 받는다. 거래 성사 보수(성공보수)는 중개 자격 문제가 있어 받지 않는다.

## 7. 단계별 작업

### A단계 — 201호 페이지 직접 만들기 (가장 먼저)

새 기능을 만들기 전에, 사장님 상가 하나를 완성해 결과를 본다. 이때 만드는 페이지 양식과 계산기는 B단계에서 그대로 다시 쓴다.

- [ ] 시작 전 코드 확인: 공개 쇼룸 화면, 문의 접수·알림, 매물 주소 구조. 재사용할 것과 새로 만들 것을 나눈다.
- [ ] 사장님에게 사실 정보와 실제 사진을 받는다(2장 입력 항목).
- [ ] 창업자용 한 장 페이지 양식을 만든다(2장 페이지 구성).
- [ ] 카페·음식점 계산기 부품을 만든다(4장 원칙).
- [ ] 문의 양식을 기존 문의 접수와 텔레그램 알림에 연결한다.
- [ ] 당근마켓·네이버 블로그 홍보글을 만든다.
- [ ] 사장님 확인 후 spacepick.kr에 올리고 홍보글을 게시한다.
- [ ] 2~4주 동안 조회 수와 문의 수를 기록한다.

완료 기준
- 페이지가 운영에 올라가고, 시험 문의 1건이 텔레그램 알림까지 도착한다.
- 계산기: 입력을 바꾸면 결과가 즉시 바뀌고, 결과가 계산식과 일치하며, 소수값·입력 범위가 정상이고, AI를 부르지 않으며, 예측이라고 표현하지 않는다.
- 휴대폰(375px)에서 가로 넘침이 없다.

### B단계 — 간단 등록과 즉시 생성 (창업자용)

A단계에서 손으로 한 일을 도구로 만든다.

- [ ] 즉시 생성 방식을 정한다(AI 호출을 대기열 없이 수 초 안에). 유료 API 사용 방식이므로 시작 전에 사용자 승인을 받는다.
- [ ] 관리자에 「간단 등록」 화면을 만든다. 2장 입력 항목 + 사진 + "누구에게".
- [ ] AI가 페이지 문구·쓰임새 제안·홍보글을 요청 즉시 만든다. 기존 AI 판매 포인트(`salesStrategy.sellingPoints`)는 즉시 생성이 동작한 뒤 연결한다.
- [ ] 계산기 선택: AI가 0~2개를 제안하고 관리자가 켜고 끈다.
- [ ] 미리보기에서 문장과 숫자를 바로 고치고 「올리기」로 공개한다.
- [ ] 기존 복잡한 흐름은 「고급」으로 숨긴다.

완료 기준: 새 매물 하나를 입력부터 공개까지 15분 안에 끝낸다. AI 대기 시간 1분 이내. 기존 게시 매물이 그대로 보인다.

### C단계 — 양식 추가와 PDF

## 10. 작업 규칙

- 작업을 시작하기 전에 이 문서를 먼저 읽는다.
- 판단 기준: **이 페이지를 본 사람이 연락하고 싶어지는가?**
- 코드를 먼저 읽고 현재 상태를 확인한다. 계획서에 있다는 이유만으로 기능을 추가하지 않는다. 재사용할 수 있으면 재사용한다.
- 한 번에 한 단계씩 진행하고, 테스트가 통과하면 다음으로 간다. 끝나면 진행 기록을 갱신한다.
- 배포, 유료 API, DB 구조 변경, 외부 서비스 설정은 사용자 승인을 받는다.
- 기능이 복잡해지거나 계획에 없는 큰 작업이 필요하면 멈추고 사용자에게 먼저 확인한다.
- 코드와 계획서가 다르면 현재 코드를 확인하고 차이를 보고한다.
- 작업이 중간에 멈추면 현재 단계와 남은 일을 진행 기록에 남기고, 다시 시작할 때 이미 한 일을 반복하지 않는다.
- 고객 자료(투자설명서, 연락처 등)는 저장소에 넣지 않는다.
- 문장은 짧게 쓴다.

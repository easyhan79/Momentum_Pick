# T10 외부 데이터·경제성 확장 요구사항

2026-11-06 기준, T10a 입력 기반 임대 가정 계산은 로컬 구현·검증 완료, T10b 외부 데이터 연결은 계약 확정 전 단계다. 현재의 지도 검색 링크는 위치 안내이며 GIS/상권 분석이 아니다. 가상의 시세·공실률·교통시간으로 빈 화면을 채우지 않는다.

| 분석 | 필요한 자료 | 먼저 정할 계약 | 공개 결과의 한계 |
| --- | --- | --- | --- |
| 위치·교통 | 주소 정규화/좌표, 도로망, 차량 제약, 경로 데이터 | 공급 API·사용권·캐시/갱신·차종·기준시간 | 검색 위치와 통행권·실측 경계 구분 |
| 토지·규제 | 지번 식별, 토지이용계획, 건축물 정보 | 공식 조회원·기준일·원문 링크·오류/누락 처리 | 허가 가능 여부를 자동 확정하지 않음 |
| 상권 | 업종별 시설·상주/유동 지표, 조사 범위와 시점 | 제공기관·범위·비용·재배포 권한 | 잠재 수요와 실제 매출 구분 |
| 물류·임대 | 임대차 계약, 공실·비교임대료, 시설·운영비 | 소유자 자료의 사용/공개 권한, 시장 비교 표본 | 총 임대료와 순수익 구분 |
| 경제성 | 매입·임대 금액, 공실 가정, 운영비, 초기 투자비 | 항목별 출처·세전/세후·기간·제외 비용·산식 | 실제 수익과 사용자 가정 시나리오 분리 |
| 조회·문의 성과 | 조회 이벤트·관심 콘셉트·문의 연결 | 수집 목적·보관기간·익명화·집계 정의 | 봇/중복 조회와 실제 문의 전환 구분 |

현재 프로젝트의 기존 가정형 계산기와 문의/CRM은 유지했다. T10a는 매입가·연 임대료·연 운영비·공실 가정을 직접 입력하고 출처/가정·공개 범위를 지정하는 선택 모듈로 추가했다. 실제 시장 데이터·공실 기본값을 만들지 않으며, 모든 필수값이 있을 때만 원 단위 운영수지를 계산한다. 금융비용·취득/소득세·초기공사비·보증금 차감은 제외한다. 이를 시장 근거가 확보된 투자수익 분석이나 완성된 성과 대시보드로 확대 해석하지 않는다.

서비스/API를 선정하기 전에는 필요한 도메인·비밀키 이름을 추정하여 환경 설정을 변경하지 않는다. 필요한 경우 기존 환경 바인딩과 실제 권한부터 확인하고 중복 인증을 요구하지 않는다. 현재 실행 환경에서 PUBLIC_DATA_API_KEY 미설정만 확인했으며, 다른 실행 환경·GitHub Actions의 비밀값 상태는 확인하지 않았다.

다음 구현 순서: 공급원/사용 조건 확정 → 비밀값 없는 어댑터 계약과 합성 응답 테스트 → 실제 읽기 요청 검증 → 항목별 출처·기준일·누락 처리 → 실제 입력과 가정 계산의 연결 → 공개 검수. 사용자 입력만으로 작동하는 T10a는 이 외부 계약과 독립적으로 구현했다. 외부 자격증명이 없어도 합성 어댑터를 만들 수 있으나, 아직 공급원이 정해지지 않아 임의의 API를 제품에 고정하지 않았다.

## 2026-11-07 보완: 유형별 분석의 범위와 우선순위

사용자는 상가·건물의 상권 분석과 토지의 입지 분석이 필요하다고 재확인했다. 원래 유형별 계획에 포함된 항목이며, T08의 정보 배치·확인 목록 완료를 실제 입지 분석 완료로 해석하지 않는다. 현재 위치 링크 및 확인 목록은 분석 기능을 대신하지 못한다.

| 대상 | 분석할 질문 | 필요한 근거 | 고객에게 설명할 결과 |
| --- | --- | --- | --- |
| 상가 | 어떤 고객·업종 수요와 경쟁 조건을 검토할 수 있는가 | 상주/직장/유동 지표, 경쟁 업종·점포, 접근·가시성·주차, 실제 임대/공실 자료 | 근거가 있는 입지 강점·약점, 업종 적합 가설, 추가 조사할 항목 |
| 건물 전체 | 임차 구성과 입지 수요가 임대 운영에 어떤 제약을 주는가 | 층별 용도·임차인·임대차/공실, 관리/설비, 주변 업무·주거 수요 | 임차 구성·운영 조건 검토와 시장 비교. 개별 상가의 업종 추천과 구분 |
| 토지 | 현재 이용 및 검토 용도에 필요한 입지 조건은 무엇인가 | 지번·지목·용도지역/규제, 실제 접도·도로폭·진입 권리, 지형/경사, 상하수도·전력 등 기반시설 | 확인된 접근/규제 조건, 이용 방향별 제약·확인사항. 개발 허가 가능 확정 아님 |

진행 단계를 나눈다.

1. **제공자료 기반 1차 분석**: 입력값·PDF/공적 자료에서 확인할 수 있는 조건을 연결해 의미와 제약을 설명한다. 자료 부족과 분석 미제공을 구분한다. 외부 유료 API 계약을 이 단계 전체의 차단 사유로 삼지 않는다. v2.1 S0~S6에서 로컬 구현·검증했다. 제공자료 규칙 기반 초안이며 실제 상권 통계 조회나 실매물 정확도 검증 완료를 뜻하지 않는다.
2. **공식/외부 데이터 보강**: 공급원별 범위·기준일·재사용 조건과 연결 권한을 확인한 뒤 실제 조회한다. 상권 수치·거리·공실률은 자료가 확보된 항목만 표시한다. 기존 GitHub PUBLIC_DATA_API_KEY 이름의 존재만으로 특정 API가 이미 연결되었다고 가정하지 않는다.
3. **관리자 검토와 공개**: 분석 근거, 대상 범위·기준일, 제공 주장과 활용 가설, 한계와 확인사항을 함께 검토한 뒤 승인본에 반영한다. AI가 상권/입지 점수를 임의 산정하거나 수요·매출·개발 가능성을 보장하지 않는다.

자료 없는 상태에서 1차 분석을 완료로 표시하거나 고정 체크리스트의 이름만 입지 분석으로 바꾸지 않는다. 실제 매물별 근거를 사용하고, 상가/건물/토지 각각의 사례로 검증해야 완료다.


## v2.1 완료 후 T10b 공급원 상태

상태는 `검토 / 접근 가능 / 계약 필요 / 연동 완료 / 운영 검증`으로 관리한다. 현재 아래 후보는 실제 읽기 접근·사용권·과금 검증 전이므로 모두 **검토**다. 특정 API를 제품에 고정하거나 접근 가능·무료·계약 완료로 간주하지 않는다.

| 후보 공급원/분야 | 상태 | 연결 전 확인할 사항 |
| --- | --- | --- |
| 공공 건축물대장 제공원 | 검토 | 조회 자격·주소/건물 매칭·응답·기준일·재이용/캐시·누락 처리 |
| 토지이용규제/공적 토지정보 제공원 | 검토 | 지번/필지 식별·규제 범위·원문·조회 제한·허가 판단 한계 |
| 공공 상가/상권정보 제공원 | 검토 | 업종 체계·지리 범위·갱신·폐업/중복·상업적 재사용 |
| 장소/지도 검색 제공원 | 검토 | 검색/좌표 권한·표시/저장 조건·비용·주소 오류 |
| 인구·세대·직장 통계 제공원 | 검토 | 집계단위·기준일·표본/추정·공개 범위·자료 사용권 |
| 차량 경로 제공원 | 검토 | 차종·도로제약·기준시간·실시간/추정 구분·과금/캐시 |
| 비교 임대/공실·거래 자료 | 검토 | 표본·기간·중개/소유자 공개 권한·비교 기준·계약 필요 여부 |

현재 분석은 승인된 공개 필드와 출처만 사용한다. 실제 수요·매출·이동시간·공실률·점수·허가 가능성을 외부 사실로 채우지 않는다. 관리자 검토와 공개 승인을 거쳐 보고서를 동결하며, 근거가 바뀐 초안은 재검토한다. 외부 연결 부재는 이 로컬 단계의 차단 사유가 아니지만 실제 시장 분석의 완료 근거도 아니다.
